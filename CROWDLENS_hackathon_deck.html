System Architecture

From Multi-Source Video to Actionable Safety Intelligence

L1 · INPUT
Recorded / uploaded video ✓ Live CCTV / RTSP ○ Drone feed ○ Multi-camera array ○
L2 · FOUNDATION
Time frame of reference — sync feeds by timestamp ○ Spatial frame of reference — camera pose & zone coverage ○
L3 · PERCEPTION
Person detection ✓ Anonymous tracking ◐ Pose estimation ○ Optical flow ✓
L4 · CROWD INTEL
Density ✓ Occupancy ✓ Demographics ○ Inflow ◐ Outflow ◐ Accumulation ✓ Compression ✓ Direction ◐ Bottleneck ◐ Edge pressure ◐
L5 · ANALYTICS
Descriptive ✓ Predictive ◐ Preemptive / what-if ◐ Prescriptive ◐
L6 · ACTION
Alerts ✓ Command center ✓ Rescue ○ Evacuation ○ Public safety ○
Time framing and spatial/camera-angle framing are the foundation for trustworthy multi-camera analytics — not built yet because today's build fuses a single feed at a time, where naive per-frame timing is sufficient. The moment a second camera joins, both layers become mandatory.

Implementation, Demo & Validation

What We Actually Built and How We Validate It

A · IMPLEMENTED
  • Multi-format upload + video library w/ categories
  • Real YOLOv8n detection (HOG+SVM fallback)
  • Density, optical-flow movement/turbulence, build-up rate, compression
  • 0–100 weighted risk score, 5-band severity
  • 4 zone bands with per-zone risk
  • Auto-alerts on RED/BLACK, acknowledge → persisted history
  • Live WebSocket + polling dashboard
  • 14/14 automated tests passing
B · PARTIALLY IMPLEMENTED
  • BYTE-style anonymous tracker — verified standalone service, not wired in
  • Bottleneck flow, reverse-flow, edge-pressure, 4-state dynamics classifier — prototype only
  • Predictive forecast + time-to-critical — unit-tested, no live UI
  • Structural-load indicator endpoint — computed, not surfaced
  • Incident escalate/resolve lifecycle — modeled, not wired
C · DESIGNED / FUTURE
  • Multi-camera time & spatial fusion
  • Live RTSP / CCTV ingestion
  • Demographic / vulnerability profiling
  • Dynamic evacuation routing
  • Public-facing safe-zone display
  • Interactive what-if scenario editor
Validation today = 14/14 automated correctness tests on the deterministic engines (risk formula, alert thresholds, scenario progression) — not accuracy against ground-truth footage. The evaluation schema stores an explicit is_measured=False flag so target metrics can never be displayed as measured results.

Privacy by Design

  • No facial recognition ✓
  • Anonymous / ephemeral tracking ✓
  • Aggregate zone analytics only ✓
  • No persistent identity profiling ✓
  • Alert audit trail ✓

Limitations

  • CCTV can't measure oxygen — asphyxia is a risk proxy, not a sensor reading
  • Structural load is an estimate, not engineering certification
  • Prototype dynamics signals need real-world validation
  • Demographic inference, if added, may carry bias — not implemented today
  • Decision support only — never a replacement for trained personnel
"We don't identify people. We identify crowd risk. CROWDLENS transforms multiple passive video sources into time-aware, spatially-aware, predictive crowd-safety intelligence — helping responders understand what is happening, what may happen next, and what action can be taken before the situation becomes critical."
Vision statement. Built today: real detection, density, dynamics and risk scoring on uploaded video. Designed next: multi-camera fusion, prediction, evacuation.
